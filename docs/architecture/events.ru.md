# События

[English version](events.md)

Событие - то, о чём компонент сообщает другим: таймер истёк, кнопку
нажали, тело вошло в триггер. Код на него подписывается, а сцена может
связать его в инспекторе без кода: "когда эту кнопку нажали, вызвать `open`
у той двери". На нём построены таймеры, интерфейс игрока (шаг 8) и физика
(шаг 6).

Пометки статуса: см. [README](README.ru.md).

## События из кода [done]

```cpp
class Score : public Script {
public:
    YQLORA_SCRIPT(Score)
    Event<int> onScored;                     // a member of the component
    void add(int points) { onScored.emit(points); }
};
YQLORA_REGISTER_SCRIPT(Score).event("onScored", &Score::onScored, {"points"});

// another component:
Connection c = score->onScored.connect(*this, [this](int points) { show(points); });
```

- **`Event<Args...>`** (`scene/Event.hpp`) - член компонента, он
  регистрируется с именами аргументов
  (`.event("onTimeout", &Timer::onTimeout)`, `EventInfo` в реестре,
  `TypeRegistry::events`). Типы аргументов - типы свойств, поэтому Luau и
  визуальные скрипты слушают через `connectValues`, который получает
  аргументы значениями `PropertyValue`.
- **Владелец** подписки - компонент: когда он уходит из сцены, его подписки
  снимаются (`Scene::exitComponent` гасит метку жизни компонента), поэтому
  обработчик уничтоженного компонента не вызывается никогда. `Connection`
  отписывается по `disconnect()` или при своём уничтожении; `release()`
  оставляет подписку жить, пока жив владелец или событие.
- **Вызов** (`emit(args...)`): сначала подписчики из кода в порядке
  подписки, затем постоянные в порядке списка. Подписчик, добавленный во
  время вызова, впервые вызывается следующим вызовом; удалённый во время
  вызова больше не вызывается. Исключение подписчика ловится и пишется в
  лог с событием и подписчиком, остальные всё равно вызываются - как
  защищены вызовы жизненного цикла.
- **Нет общей шины сообщений**: событие принадлежит компоненту, поэтому
  кто может его вызвать и кто слушает, видно в коде и в инспекторе.

## Постоянные подписчики [done]

- `.event(...)` добавляет и свойство с именем события
  (`PropertyHint::EventTargets`): список `EventTarget`, у каждого - узел
  (`NodeRef`), сам узел или его компонент по `ComponentId` и имя метода.
  Раз это свойство, список сохраняется со сценой, правится в инспекторе с
  отменой и копируется в Play; цель внутри префаба переводится, как любой
  `NodeRef` (см. [префабы](prefabs.ru.md)).
- Когда событие вызвано, метод каждой цели вызывается через реестр
  (`Method::call`). Метод с параметрами получает аргументы события, без
  параметров - вызывается без них, то есть слушает любое событие. Цель,
  которой нет или чей метод не подходит, пропускается, а лог сообщает о ней
  один раз, а не на каждом вызове.
- **Только в идущей сцене**: постоянные подписчики вызываются там, где
  стоит `Scene::playing()` (копия Play, игра; ставят `PlayMode` и
  `GameRuntime`), никогда в редактируемой сцене редактора.

## Редактор [done]

- Свойство-событие показывает постоянных подписчиков списком
  (`EventTargetsField`): у каждого поле узла (узел бросают на него из
  дерева), затем сам узел или один из его компонентов, затем метод,
  который слушает событие (`eventMethods`: без результата и без параметров
  или с типами параметров события по порядку), с именами параметров;
  кнопка удаляет строку. "Добавить" внизу тоже принимает брошенный узел.
  Один шаг отмены на изменение.
