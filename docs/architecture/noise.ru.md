# Шумы

[English version](noise.md)

Процедурные шумы для всего движка: в C++ и скриптах, текстурой для
материалов и функциями в шейдерах. Один набор алгоритмов даёт одни и те же
значения везде.

Пометки состояния: см. [README](README.ru.md).

## Решения [planned, after step 5]

- **Один источник алгоритмов**: [FastNoiseLite](https://github.com/Auburn/FastNoiseLite)
  (MIT), закреплён на коммите, как остальные библиотеки. В нём одни и те же
  алгоритмы есть заголовком C++ и файлом GLSL, поэтому шум, построенный в
  C++, и тот же шум, посчитанный в шейдере, совпадают (с точностью float).
  Своих копий алгоритмов движок не пишет.
- **Настройки - одна запись**, `NoiseSettings`, зарегистрированная в реестре
  типов. Класс C++, поле скрипта, ресурс шума и текстура шума держат эту
  запись, поэтому инспектор, файлы и скрипты видят один список полей.
- **Три уровня, не смешиваются**: `Noise` (значения в точках, без файлов и
  GPU), ресурс шума `.ynoise` (настройки в файле, общие для скриптов и
  текстур), текстура шума `.ynoisetex` (картинка из шума, обычная текстура
  для материалов).
- **Значения в [-1, 1]** у всех видов; текстура переводит их в [0, 1] (или
  в [min, max] после нормировки).

## Настройки

`NoiseSettings` (запись, у каждого поля значение по умолчанию и диапазон):

- `kind`: `OpenSimplex2`, `OpenSimplex2S`, `Cellular`, `Perlin`,
  `ValueCubic`, `Value`;
- `seed` (int), `frequency` (float), `offset` (vec3, сдвигает шум в
  пространстве, не меняя его вида);
- фрактал: `fractal` (`None`, `FBm`, `Ridged`, `PingPong`), `octaves`,
  `lacunarity`, `gain`, `weightedStrength`, `pingPongStrength`;
- ячеистый: `cellularDistance` (`Euclidean`, `EuclideanSq`, `Manhattan`,
  `Hybrid`), `cellularReturn` (`CellValue`, `Distance`, `Distance2`,
  `Distance2Add`, `Distance2Sub`, `Distance2Mul`, `Distance2Div`),
  `cellularJitter`;
- искажение области: `warp` (`None`, `OpenSimplex2`, `OpenSimplex2Reduced`,
  `BasicGrid`), `warpAmplitude`, `warpFrequency`, `warpFractal` (`None`,
  `Progressive`, `Independent`), `warpOctaves`, `warpLacunarity`,
  `warpGain`.

Значения перечислений пишутся по имени (`YQLORA_ENUM_NAMES`), так что файлы
читаемы, а порядок в C++ можно менять.

## Шум в коде

```cpp
yqlora::Noise noise({.kind = NoiseKind::Perlin, .seed = 7, .frequency = 0.05f});
float height = noise.sample(x, z);          // 2D
float density = noise.sample(position);     // 3D, Vec3
Vec3 warped = noise.warp(position);         // только искажение области
```

- `Noise` (`engine/include/yqlora/math/Noise.hpp`) - значение: на входе
  настройки, на выходе числа. `sample` константный, его можно вызывать из
  нескольких потоков.
- `setSettings` заменяет все настройки сразу; сеттеров по полям, которые
  оставили бы объект изменённым наполовину, нет.
- Скрипт берёт шум из ресурса (`resource.noise()`) или держит своё поле
  `NoiseSettings`, которое инспектор показывает как любую запись.
- Luau и визуальные скрипты получают `Noise` через привязки, построенные по
  реестру (его методы зарегистрированы), без ручного кода.

## Ресурс шума

Файл `.ynoise` (JSON, `FileFormat` версии 1) хранит одну `NoiseSettings`:

```json
{
    "kind": "Perlin",
    "seed": 7,
    "frequency": 0.05,
    "fractal": "FBm",
    "octaves": 4,
    "version": 1
}
```

- Создаётся в Файлах ("Создать ресурс > Шум") через окно создания, лежит
  где угодно в проекте.
- Поле, которого нет в файле, берёт значение по умолчанию; поле, которого
  больше нет в записи, остаётся в файле и записывается обратно (как у
  материалов).
- Изменение поднимает ревизию; текстуры шума, которые его используют,
  строятся заново.

## Текстура шума

Файл `.ynoisetex` - текстура, построенная из шума. Слоты материала берут её
так же, как `.png`: у неё вид текстуры, и `ResourceCache` хранит её
`TextureData`.

```json
{
    "noise": "4c1e07a95b3d2f60",
    "width": 512,
    "height": 512,
    "dimensions": "2D",
    "seamless": true,
    "seamlessBlend": 0.1,
    "invert": false,
    "normalize": true,
    "output": "Color",
    "bumpStrength": 8.0,
    "colorSpace": "Linear",
    "version": 1
}
```

- `noise` - ссылка на `.ynoise`, или файл держит свою `NoiseSettings` в
  `settings`, когда общий шум не нужен; одновременно оба нельзя.
- `seamless`: картинка повторяется без шва. В FastNoiseLite нет 4D шума,
  чтобы брать значения на торе, поэтому картинка строится больше, а её края
  смешиваются с противоположными на долю размера `seamlessBlend` (от 0 до
  1).
- `normalize`: значения картинки растягиваются в [0, 1] по их настоящему
  минимуму и максимуму.
- `output`: `Color` (серый, одно значение в RGB) или `NormalMap` (карта
  нормалей в касательном пространстве по высоте, сила `bumpStrength`, +Y
  вверх, как ждёт `normalMap` у `Standard`).
- `dimensions`: сейчас `2D`; `3D` (объёмная текстура) ждёт 3D текстур в
  RHI.
- Картинка строится синхронно, строки делятся между потоками; размер
  ограничен 4096 x 4096. Фоновое построение придёт вместе с фоновой
  загрузкой ресурсов.
- Градиент (цветовая шкала) на выходе - отдельный ресурс позже; тогда в
  файле появится ссылка `gradient`, без новой версии формата.

## В шейдерах

```glsl
#include <yqlora/noise.glsl>

fnl_state state = fnlCreateState(7);
state.noise_type = FNL_NOISE_PERLIN;
state.frequency = 0.05;
float value = fnlGetNoise3D(state, position.x, position.y, position.z);
```

- `<yqlora/noise.glsl>` - файл GLSL из FastNoiseLite без изменений, лежит в
  библиотеке шейдеров движка. Имена в нём свои, поэтому его документация
  подходит как есть.
- Материал не передаёт шейдеру ресурс шума: шейдер держит свои параметры в
  блоке `Material`, как любые значения, или читает текстуру шума.

## Редактор

- Инспектор `.ynoise` и `.ynoisetex` показывает поля записи и превью
  (256 x 256, строится заново после правки, не чаще раза за кадр); правки
  сразу идут в файл, как у материалов.
- Файлы показывают текстуру шума её картинкой вместо значка.

## Фазы (коммит на фазу)

### N.1 Шум в коде

- Подключён FastNoiseLite (файлы C++ и GLSL, закреплён один коммит), его
  лицензия в списке сторонних библиотек.
- `NoiseSettings` с перечислениями и именами, зарегистрирована как запись;
  `Noise` с `sample` 2D и 3D и `warp`.
- **Тесты**: одинаковые настройки и seed дважды дают одинаковые значения;
  каждый вид даёт значения в [-1, 1] на сетке точек; другой seed меняет
  значения; `offset` сдвигает шум (`sample(p + offset)` одного равен
  `sample(p)` другого); `NoiseSettings` проходит через JSON и обратно.

### N.2 Ресурс шума и текстура шума

- Загрузчики `.ynoise` и `.ynoisetex`, виды ресурсов, ревизии и зависимость
  текстуры от её шума (новая ревизия шума перестраивает текстуру).
- Построение картинки: `Color`, `NormalMap`, `seamless`, `invert`,
  `normalize`.
- **Тесты**: у текстуры шума заданный размер; `seamless` даёт равные
  значения на противоположных краях; `normalize` даёт минимум 0 и максимум
  1; `NormalMap` плоского шума равна (0.5, 0.5, 1); изменённый `.ynoise`
  даёт новую ревизию текстуры; материал берёт текстуру шума в слот.

### N.3 Шум в шейдерах

- `<yqlora/noise.glsl>` в библиотеке движка, компилируется тем же
  компилятором и профилем.
- **Тесты**: шейдер с `noise.glsl` компилируется; на OpenGL шейдер на весь
  экран, который пишет `fnlGetNoise2D`, даёт значения `Noise` в тех же
  точках с точностью 1e-3.

### N.4 Редактор и документы

- Создание обоих ресурсов в Файлах, инспекторы с превью, значки.
- Документы: этот файл (пометки [done]), ресурсы, проект (оба формата),
  руководство "Шум в скриптах, материалах и шейдерах", README.
