# Постобработка

[English version](post-processing.md)

Эффекты поверх нарисованной картинки камеры: автоэкспозиция, bloom,
сглаживание, глубина резкости, размытие в движении, цветокоррекция,
виньетка и зерно, а также свои эффекты игры; плавно меняются зонами в
сцене. Это часть постобработки из
[фотореализма по умолчанию](rendering.ru.md#фотореализм-по-умолчанию-planned-after-the-mvp).

## Решения [planned, after the MVP]

- **Каждый эффект - своя запись и свой проход.** Эффект - запись настроек
  (`Bloom`, `AutoExposure`, `DepthOfField`, ...) с выключателем `enabled`
  и проход графа отрисовки, который их читает. Новый эффект - новая запись
  и новый проход и одна строка в списке эффектов; больше ничего не
  меняется. Каждый эффект можно выключить, все его параметры открыты;
  реалистичные значения - только значения по умолчанию.
- **Настройки складываются стопкой.** Настройки кадра камеры считаются
  каждый кадр: значения проекта по умолчанию (Graphics), затем
  собственные `PostProcessSettings` камеры, затем объёмы, которые
  накрывают камеру, по приоритету, каждый со своим весом. Поле записи
  заменяется, только если стоит его флаг замены, поэтому объём, который
  меняет лишь силу bloom, больше ничего не трогает. Смешивание делает над
  записями реестр (числа и цвета линейно, выключатели и перечисления на
  половине веса): один код на все эффекты, без своего смешивания у
  каждого.
- **Объёмы - компоненты.** `PostProcessVolume` на `Node3D`: форма
  (`Global`, `Box`, `Sphere`), `blendDistance` (камера вводит объём на
  этом расстоянии снаружи формы), `weight`, `priority` и заменённые
  записи. Пещера темнее и синее, размытие и цвет под водой, эффект
  отравления через `weight` из кода.
- **Где они идут.** В графе отрисовки вида:
  ```
  непрозрачное (+ векторы движения) -> небо -> прозрачное
    -> [HDR, линейно] замер яркости автоэкспозиции, TAA,
       глубина резкости, размытие в движении, bloom, свои "BeforeToneMap"
    -> вывод: тональная компрессия, LUT цветокоррекции, sRGB
    -> [LDR] FXAA, виньетка, зерно, хроматическая аберрация,
       дисторсия объектива, свои "AfterToneMap"
    -> HUD, проходы редактора
  ```
  Эффекты в HDR работают в линейном свете; те, что после, - вид итоговой
  картинки.
- **Что нужно кадру** - добавляется в рендер один раз для всех эффектов:
  чтение цели глубины в проходе; векторы движения (цель `Rg16Float`,
  которую пишет проход непрозрачного по нынешней и прошлой мировой
  матрице каждого элемента и прошлой проекции вида); дрожание проекции для
  TAA; текстуры истории, живущие между кадрами одного вида (постоянная
  текстура, которую каждый кадр подключают в `RenderGraph`); цепочка мипов,
  которую делает проход (уменьшение для bloom и экспозиции); 3D-текстуры
  для LUT цветокоррекции. Extract остаётся без памяти: прошлые матрицы
  хранит рендер, по видам, по ID узла и подмешу.
  `Transform3D::teleport` (новый вызов: поставить позу и отметить прыжок;
  им пользуются телепорты физики и ригов) даёт элементам узла нулевое
  движение в этот кадр, поэтому монтажная склейка не оставляет смаза.
- **Автоэкспозиция без вычислительных шейдеров.** Логарифм яркости
  HDR-картинки сводится цепочкой проходов уменьшения к одному текселю;
  приспособленное значение движется к нему со `speedUp` или `speedDown` и
  хранится в текстуре истории 1 x 1. Шейдеры берут экспозицию из этой
  текстуры через `exposure()` из `uniforms.glsl`, и для ручной экспозиции
  тоже (её значение пишется туда же), поэтому путь один и без ветвлений.
  Кадр рисуется с экспозицией прошлого кадра: на кадр позже, что при
  скоростях приспособления не видно. Это ещё один режим экспозиции камеры
  (`Auto` рядом с ручной EV), с `minEV`, `maxEV`, `compensation` и маской
  замера (по умолчанию с весом к центру). Гистограмма на вычислительных
  шейдерах придёт позже за теми же настройками.
- **Цветокоррекция - LUT.** Баланс белого, lift, gamma, gain, контраст,
  насыщенность, сдвиг оттенка, кривые и файл LUT `.cube` по желанию
  запекаются в одну 3D LUT (32 ячейки), когда меняются настройки, и
  применяются в проходе вывода после тональной компрессии. Десять
  значений цветокоррекции стоят столько же, сколько одно.
- **Свои эффекты игры - материалы.** Шейдер постобработки - `.yshader` с
  `#include <yqlora/post.glsl>`: он получает цвет прошлого прохода,
  глубину, векторы движения, UV и размер экрана и пишет цвет.
  `PostProcessEffect` в стопке хранит материал такого шейдера, его точку
  (`BeforeToneMap`, `AfterToneMap`), порядок и `intensity`: результат
  смешивается с картинкой до него по `intensity`, которая смешивается в
  объёмах как любое число. Собственные параметры материала не
  смешиваются: их меняют из кода. Контур, пиксельный вид, марево, волна
  сканера - без кода движка.
- **Редактор и игра одинаковы.** Окно сцены пользуется постобработкой
  главной камеры, с объёмами по месту камеры редактора (переключатель в
  меню окна вида, по умолчанию включён); окно игры и собранная игра -
  постобработкой своей камеры.

## Эффекты

- **`AutoExposure`**: выше.
- **`Bloom`**: порог с мягким коленом, сила, рассеяние, оттенок, текстура
  грязи на объективе с её силой; последовательное уменьшение и увеличение
  с фильтром на 13 выборок (без мерцания на мелких ярких точках).
- **`Antialiasing`**: `None`, `FXAA` (дёшево, после тональной
  компрессии), `TAA` (дрожание, перепроецирование по векторам движения,
  ограничение по соседям, доля резкости). По умолчанию TAA; цель MSAA с
  постобработкой не используется.
- **`DepthOfField`**: расстояние фокуса (или узел фокуса), диафрагма
  (f-число) и фокусное расстояние (из угла обзора камеры и её
  `sensorSize`, по умолчанию 36 мм), поэтому размытие следует настоящему
  объективу; боке выборкой по диску с числом лепестков; ближнее и дальнее
  размытие отдельно.
- **`MotionBlur`**: сила как угол затвора, число выборок, доля камеры и
  доля объектов отдельно.
- **`ColorGrading`**: выше.
- **`Vignette`**, **`FilmGrain`**, **`ChromaticAberration`**,
  **`LensDistortion`**: сила и немного полей формы.
- Затенение окружением (SSAO), отражения в экранном пространстве и туман
  относятся к части освещения этапа фотореализма, а не сюда; они
  подключаются к той же стопке настроек.

## Из кода

- `Camera3D::postProcess()` - настройки камеры, каждая запись и поле,
  чтение и запись.
- `PostProcessVolume`: `weight`, `priority`, форма, записи; игра вводит
  эффект, анимируя `weight`.
- `scene.postProcess().settingsAt(camera)` - смешанные настройки этого
  кадра (для своего эффекта игры, которому они нужны).
- Материал своего эффекта меняется как любой материал
  ([материалы из скриптов](materials.ru.md#материалы-из-скриптов-done)).

## Редактор

- Инспектор камеры и объёма показывает записи свёртками, каждое поле с
  флажком замены (в объёме), а запись - со своим `enabled`.
- Гизмо объёма - его форма и расстояние смешивания вторым, бледным
  контуром.
- "Создать > Объём постобработки" и "Создать > Шейдер > Эффект
  постобработки" (шаблон с `post.glsl`).

## Где кончается движок и начинается игра

Движок даёт эффекты, стопку настроек с объёмами и смешиванием и способ
добавить свой эффект игры материалом. Какой у игры вид, когда вводится
эффект (удар, мало здоровья, сон) и свои эффекты игры - это игра.

## Фазы (коммит на фазу)

### PP.1 Стопка и нужды кадра

- Записи эффектов с флагами замены, смешивание реестром, настройки
  камеры, `PostProcessVolume`, значения проекта по умолчанию; чтение
  глубины, постоянные текстуры истории, проход уменьшения, `exposure()`
  из текстуры.
- Тесты: поле без флага замены сохраняет значение ниже; два объёма
  смешиваются по весу и приоритету; камера снаружи объёма на половине его
  `blendDistance` получает половину его веса; выключатели переключаются
  на половине веса; настройки вида без объёмов равны настройкам камеры;
  текстура истории хранит содержимое до следующего кадра того же вида;
  ручная экспозиция через текстуру рисует ту же картинку, что и раньше.

### PP.2 Автоэкспозиция и bloom

- Цепочка яркости, приспособление, экспозиция из текстуры, режим
  экспозиции `Auto`; bloom.
- Тесты: сцена вдвое ярче приходит к вдвое меньшей экспозиции в пределах
  `minEV` и `maxEV`; приспособление длится время, которое даёт его
  скорость; `compensation` +1 удваивает экспозицию; bloom пикселя выше
  порога разносит свет вокруг, а пикселя ниже - нет; выключенный эффект
  убирает свой проход из графа.

### PP.3 Векторы движения и сглаживание

- Цель скоростей, прошлые матрицы в рендере, отметка телепорта, дрожание
  проекции, TAA, FXAA.
- Тесты: неподвижная сцена при движущейся камере даёт векторы движения,
  совпадающие с движением камеры; векторы движущегося объекта совпадают с
  его движением; телепортированный узел не даёт вектора (нет смаза после
  склейки); TAA неподвижной сцены сходится к среднему кадров с дрожанием.

### PP.4 Глубина резкости, размытие в движении и вид

- Глубина резкости, размытие в движении, виньетка, зерно, хроматическая
  аберрация, дисторсия объектива.
- Тесты: точка на расстоянии фокуса остаётся резкой, а далёкая от него
  размыта на кружок нерезкости объектива; размытие в движении нулевой
  силы ничего не меняет; каждый эффект вида при силе 0 ничего не меняет
  (в сравнении с выключенным проходом).

### PP.5 Цветокоррекция и свои эффекты

- 3D-текстуры в RHI, запекание LUT, загрузка `.cube`, `post.glsl`,
  `PostProcessEffect`, шаблон шейдера "Эффект постобработки".
- Тесты: нейтральная цветокоррекция даёт тождественную LUT; насыщенность
  0 даёт серое; файл `.cube` загружается и применяется; свой эффект,
  обращающий цвета, идёт в своей точке и своём порядке; его `intensity`
  смешивается в объёме, а при 0 проход пропускается.

### PP.6 Редактор и документы

- Инспекторы с флажками замены, гизмо объёма, постобработка в окне сцены,
  пункты "Создать"; руководство "Постобработка", этот файл - [done].
- Тесты (логика без интерфейса): включение замены берёт нынешнее значение
  как начальное; окно сцены пользуется стопкой главной камеры.
